## 1. Time and Space Complexity

### What is Complexity?

Complexity tells us how much **time** and **memory** an algorithm needs as the input size grows.

- **Time Complexity** → how the running time grows.
- **Space Complexity** → how much extra memory the algorithm needs.

We usually express complexity using **Big O notation**.



## 2. Asymptotic Notations

### Big O — `O(...)`

Big O describes an **upper bound** on growth and is commonly used to describe the worst-case complexity.

Example:


for element in array:
    print(element)


This visits all `n` elements, so the time complexity is:

**O(n)**

### Big Omega — `Ω(...)`

Big Omega describes a **lower bound** on growth. It is often used when discussing the best-case behavior.

Example: accessing the first element of a Python list:


array[0]


This takes constant time:

**Ω(1)**

### Big Theta — `Θ(...)`

Big Theta describes a **tight bound**, meaning the growth rate is bounded both above and below by the same order.

For example:

**Θ(n)**

> Important: `O(n/2)` is still `O(n)` because constant factors are ignored in asymptotic analysis.



# 3. Common Time Complexities

## O(1) — Constant Time

The operation takes approximately the same amount of time regardless of input size.


array = [1, 2, 3, 4, 5]
print(array[0])


**Time Complexity: O(1)**

Examples:
- Accessing a list element by index
- Dictionary lookup on average
- Stack push/pop



## O(log n) — Logarithmic Time

The amount of work grows slowly as the input grows. The problem size is usually reduced by a factor each step.

A classic example is **Binary Search** on a sorted array.


100 elements
   ↓
50
   ↓
25
   ↓
12
   ↓
6
   ↓
3
   ↓
1


**Time Complexity: O(log n)**

> Important correction: simply visiting every third element is **O(n)**, not O(log n).



## O(n) — Linear Time

The work grows directly with the number of elements.


array = [1, 2, 3, 4, 5]

for element in array:
    print(element)


Every element is visited once.

**Time Complexity: O(n)**



## O(n log n)

A common complexity for efficient sorting algorithms.

Examples:
- Merge Sort
- Heap Sort
- Average-case Quick Sort

**Time Complexity: O(n log n)**



## O(n²) — Quadratic Time

Usually occurs when one loop runs inside another loop.


for x in array:
    for y in array:
        print(x, y)


For `n` elements, approximately `n × n` operations are performed.

**Time Complexity: O(n²)**

Common examples:
- Bubble Sort
- Selection Sort
- Comparing every pair of elements



## O(2ⁿ) — Exponential Time

The amount of work can approximately double as the input grows.

A classic example is the naive recursive Fibonacci implementation:


def fibonacci(n):
    if n <= 1:
        return n

    return fibonacci(n - 1) + fibonacci(n - 2)


**Time Complexity: O(2ⁿ)**

> `O(2n)` is linear, not exponential. Exponential complexity is written as `O(2ⁿ)`.



# 4. Complexity Order

From generally faster to slower growth:


O(1)
 ↓
O(log n)
 ↓
O(n)
 ↓
O(n log n)
 ↓
O(n²)
 ↓
O(2ⁿ)
 ↓
O(n!)
```

When choosing an algorithm, we generally prefer a lower growth rate for large inputs.



# 5. Space Complexity

Space complexity describes how much memory an algorithm uses.

There are two useful ideas:

### Input Space

Memory required to store the input itself.

For `n` elements:

**O(n)**

### Auxiliary Space

Extra memory used by the algorithm apart from the input.

Example:


total = 0

for value in array:
    total += value


The algorithm uses only a few extra variables.

**Auxiliary Space: O(1)**

# 7. Important Python Data Structures

## List

A list is an ordered and mutable collection.


numbers = [10, 20, 30, 40]


Common operations:


numbers.append(50)
numbers.pop()
numbers[0]
numbers.sort()


Important complexity:

| Operation | Average Time |
|---|---:|
| Access by index | O(1) |
| Append | O(1) amortized |
| Insert at beginning | O(n) |
| Search | O(n) |
| Delete from beginning | O(n) |



## Tuple

A tuple is an **ordered and immutable** collection.


data = (10, 20, 30)


After creation, its elements cannot be changed.

Useful when the collection should not be modified.



## Set

A set stores **unique** elements.


numbers = {10, 20, 30}


Example:


numbers.add(40)

Average-case membership testing:


20 in numbers


**Average Time: O(1)**



## Dictionary

A dictionary stores data as **key-value pairs**.


student = {
    "name": "Shiva",
    "age": 21
}

Access:


print(student["name"])


Average-case lookup, insertion, and deletion are generally:

**O(1)**



# 8. Linked List

A **Linked List** is a linear data structure made up of nodes.

Each node contains:

- **Data** → stores the value
- **Link/Next** → stores a reference to another node


Head
 ↓
10 → 20 → 30 → NULL


## Node

A node is the basic element of a linked list.


┌────────┬────────┐
│  Data  │  Next  │
└────────┴────────┘


In Python:


class Node:

    def __init__(self, value):
        self.data = value
        self.next = None


## Head

`head` points to the first node.

## Tail

`tail` points to the last node.



# 9. Types of Linked Lists

## Singly Linked List

Each node points to the next node.


10 → 20 → 30 → NULL


Direction: Forward only.

## Doubly Linked List

Each node has a previous and next reference.


NULL ← 10 ⇄ 20 ⇄ 30 → NULL


Direction: Forward and backward.

## Circular Singly Linked List

The last node points back to the first node.


      ┌───────────────┐
      ↓               │
10 → 20 → 30 → 40 ────┘


## Circular Doubly Linked List

Each node has previous and next references, and the list forms a circle.



# 10. Linked List Operations

Important operations:

- Traversal
- Insertion
- Deletion
- Searching
- Updating
- Reversing

### Traversal


temp = head

while temp is not None:
    print(temp.data)
    temp = temp.next


Use a temporary reference such as `temp` so that the original `head` is not lost.



# 11. Linked List Complexity

### Singly Linked List

| Operation 			| Time 		| Auxiliary Space |
|---|---:|---:|
| Access by index 		| O(n) 		| O(1) |
| Search 			| O(n) 		| O(1) |
| Traversal 			| O(n) 		| O(1) |
| Insert at beginning 		| O(1) 		| O(1) |
| Insert at end with tail	| O(1) 		| O(1) |
| Insert at end without tail 	| O(n) 		| O(1) |
| Delete at beginning 		| O(1) 		| O(1) |
| Delete at end 		| O(n) 		| O(1) |
| Delete by value 		| O(n) 		| O(1) |

**Space required to store n nodes: O(n).**



# 12. Tree

A **Tree** is a nonlinear data structure used to represent hierarchical relationships.

A tree does not contain cycles.

Common examples:
- File and folder structures
- Organization hierarchies
- HTML/XML document structures

Important terms:

- **Root** → top node
- **Parent** → node with child nodes
- **Child** → node connected below a parent
- **Leaf** → node with no children
- **Edge** → connection between two nodes
- **Depth** → distance from the root to a node
- **Height** → longest path from a node to a leaf



# 13. Binary Tree

A **Binary Tree** is a tree in which each node has **at most two children**.

The two children are commonly called:

- Left child
- Right child


        10
       /  \
     20    30
    /  \
   40   50


Binary trees are the foundation for structures and algorithms such as:

- Binary Search Trees
- Heaps
- Expression Trees
- Syntax Trees
- Huffman Coding



# 14. Binary Search Tree (BST)

A **Binary Search Tree** is a binary tree that follows an ordering rule.

For a common BST with unique values:


Left subtree < Root < Right subtree


Example:


             70
            /  \
          50    90
         /  \   / \
       30   60 80 100
      /  \
     20  40


For every node:
- Smaller values go to the left.
- Larger values go to the right.

If duplicates are allowed, the implementation must define a consistent rule for where equal values go.



# 15. BST Traversals

## Depth-First Search (DFS)

### Preorder


Root → Left → Right


For the above tree:


70 → 50 → 30 → 20 → 40 → 60 → 90 → 80 → 100


### Inorder


Left → Root → Right

Output:


20 → 30 → 40 → 50 → 60 → 70 → 80 → 90 → 100


For a BST, inorder traversal produces values in sorted order when the BST ordering is valid.

### Postorder


Left → Right → Root


Output:


20 → 40 → 30 → 60 → 50 → 80 → 100 → 90 → 70




# 16. Breadth-First Search (BFS)

**Level Order Traversal** visits nodes level by level.

For the example tree:


70 → 50 → 90 → 30 → 60 → 80 → 100 → 20 → 40


BFS is commonly implemented using a **queue**.


# 17. BST Complexity

Let `h` be the height of the tree.

| Operation | Average / Balanced | Worst Case |
|---|---:|---:|
| Search | O(log n) | O(n) |
| Insert | O(log n) | O(n) |
| Delete | O(log n) | O(n) |
| Traversal | O(n) | O(n) |

### Why can BST become O(n)?

If values are inserted in already sorted order:


10
  \
   20
     \
      30
        \
         40
           \
            50


The tree becomes similar to a linked list.

Therefore, ordinary BST operations can become **O(n)** in the worst case.

Balanced trees such as AVL Trees and Red-Black Trees are designed to keep height near `O(log n)`.



# 18. Graph

A **Graph** consists of a set of **vertices (nodes)** and **edges** that connect pairs of vertices.


A ─── B
│ \   │
│  \  │
C ─── D


Important terms:

- **Vertex** → a node in a graph
- **Edge** → connection between vertices
- **Degree** → number of edges connected to a vertex
- **Path** → sequence of connected vertices
- **Cycle** → path that returns to the starting vertex



# 19. Types of Graphs

## Directed Graph

Edges have a direction.

text
A → B


## Undirected Graph

Edges have no direction.

text
A ─ B


## Weighted Graph

Edges have values such as cost or distance.

text
A ──5── B


## Unweighted Graph

Edges do not have weights.

Graphs can also contain positive or negative edge weights, depending on the problem.



# 20. Graph Representation

## Adjacency Matrix

An adjacency matrix is a 2D matrix used to represent connections between vertices.

Example:

text
     A B C
A    0 1 1
B    1 0 0
C    1 0 0
```

`1` means an edge exists and `0` means no edge.

### Space Complexity

**O(V²)**

where `V` is the number of vertices.



## Adjacency List

An adjacency list stores the neighbors of each vertex.

Example:

python
graph = {
    "A": ["B", "C"],
    "B": ["A"],
    "C": ["A"]
}


### Space Complexity

For a standard adjacency-list representation:

**O(V + E)**

where:
- `V` = vertices
- `E` = edges

Adjacency lists are generally more memory-efficient for sparse graphs.

text

        ↓

        ↓
3. Try a simple/brute-force solution
        ↓

        ↓

        ↓

        ↓
